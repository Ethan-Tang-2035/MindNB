# 画布对象：文档 = 树 + 游离集合 + 画布对象

后续扩展：[ADR-0007](0007-embedded-structured-content.md) 允许图片、贴纸等内容归属于节点内部；本文关于它们仅作为独立画布对象的范围被扩展，其余独立画布对象语义保留。

复现手绘信息图海报（插图、贴纸、气泡/云朵等形状、虚线分组框、自由箭头）需要「不是节点的画布元素」。树与游离集合装不下它们：游离节点仍是「带文字的主题框」，插图没有文字，分组框圈住别人，关系线连着别人。决定把文档模型再扩一层：`MindMap.objects?: CanvasObject[]`，与 `floating` 同级，进同一套撤销快照与存储 schema（可选字段，存量文档零迁移）。

对象类型按「图里长什么样」定四种：`image`（位图，压缩后以 data URL 随文档存）、`sticker`（内置手绘图标，代码内矢量路径，非数据）、`group`（分组框）、`edge`（关系线，两端引用对象 id 或任意节点 id）。数组顺序即对象间 z 序，置顶/下移就是重排数组。

三个刻意取舍：

- **分组框用几何包含而非成员清单**：拖框时把「按下瞬间盒中心落在框内」的游离头与对象一起带走。成员清单要在挂接/删除/缩放时维护一致性，几何式零维护；代价是「先把树节点摆进框」不存在——分组框永不圈树上的节点（树坐标是布局的，框圈不住）。
- **关系线随端点存亡**：任一端对象/节点被删，线级联删除（removeSubtrees 与 removeObjects 内统一清悬空引用），不做悬空半截线——单人产品里悬空线只有困惑没有用处。
- **图片存 data URL 而非独立资源库（grill Q2）**：粘贴/上传即压缩（长边 ≤1024、JPEG q0.85），localStorage 5MB 配额内够单人插图用量；将来真触顶再机械迁移 IndexedDB，成本可控。

渲染层序（自底向上）：分组框 → 树连线 → 关系线 → 树节点 → 图片/贴纸。选中/拖动命中按同序的逆序（顶层先中）。键盘导航网（nav.ts）不覆盖对象——对象一律鼠标选中，与游离节点同款心智。
