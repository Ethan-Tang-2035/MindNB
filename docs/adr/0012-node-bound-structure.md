# ADR-0012 结构绑定节点：最近祖先继承 + 容器退化 + 侧别钉定

现状布局模式是文档级三选一（right/left/balanced），`assignSide`（layout.ts）自动贪心分侧，用户无法为某个分支指定结构或左右侧。XMind 的模型是「每个分支都可以是一个独特的结构」——结构绑定在主题上、只作用于其后代（调研：XMind 官方博客《如何在 Xmind 中结合不同的结构以及为什么》、帮助中心 "To change a Branch's Structure: Select the Branch Root Topic"、user-guide 对骨架/结构的二分：骨架=全局样式、结构=可作用于任意主题的信息组织）。决定把布局模式改造为**绑定节点的结构**，自动平衡降级为缺省分配。节点结构与继承的实现见 `src/layout.ts` 及其回归测试。

## 决策

- **结构词表（首版 9 种）**：right / left / map（思维导图·平衡）/ orgUp / orgDown（组织结构图·上/下）/ treeRight / treeLeft（树形图·左/右）/ fishRight / fishLeft（鱼骨图·右头/左头）；时间线、矩阵入 backlog。
- **解析链**：节点显式 structure > 最近祖先的显式设置 > 文档默认结构 > right——与分支形状「头覆盖」解析链（ADR-0009）同构。
- **容器型结构退化**：map 与鱼骨被（非显式）继承到深层时退化为方向延续——map 按所在侧退化为 right/left，鱼骨沿主刺方向延续；只有显式设置的节点才是新的平衡中心/鱼骨头。否则会产生嵌套鱼刺与深层错位（原型冒烟已验证）。
- **侧别钉定**：`sideOverride: 'left'|'right'` 仅当父节点生效结构为 map 时有意义；自动平衡（贪心按子树高度、平手放右，沿用 assignSide 惯例）只分配未钉定分支；钉定后左右数量不必相同；拖节点越过父节点中线即换侧（拖动中实时重排预示），面板可设回「自动」。
- **鱼骨深层形态**：子项垂直挂在肋排上（近似 XMind）；原型的「沿刺水平流」仅为示意。
- **几何导航**：方向键按屏幕几何方向移动（组织结构图里上下键纵向走）；Tab/Shift+Tab 仍按树的深度优先序。
- **术语**：UI 与词表用「结构」，「布局模式」退役为旧称；独立主题的 `IndependentTopic.layoutMode` 统一迁入节点 structure（值域为新词表子集，存量读取迁移）。
- 结构与侧别变更进撤销历史，遵循 v9 文档属性惯例。

## 刻意取舍

- 放弃「结构只允许设在分支头（一级）」——XMind 允许任意主题设结构，深层设置正是多结构混排的价值。
- 放弃「平衡 = 左右数量相同」——用户可钉侧（2025-09-09 第二轮反馈明确），自动平衡只是缺省分配。
- 放弃「父级结构不往下传」（只看文档默认）——最近祖先继承与分支形状解析链同构，直觉且实现同构。

## Consequences

- 存量文档渲染不变（结构字段缺省 = 文档级 `layoutMode` 语义），但独立主题字段迁移后 schema 需要读取兼容。
- 磁吸挂接、外框/概要跟随、导航缩略图必须按「结构可以逐段变化」的树重排，不能再假设全图单一方向。
