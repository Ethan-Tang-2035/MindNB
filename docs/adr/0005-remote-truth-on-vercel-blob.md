# 远端真源：Vercel Blob + 应用层密钥鉴权

导图原存 localStorage（延续 ADR-0001 的布局），为跨设备使用，真源移到远端：浏览器经自有 API Routes 读写 Vercel Blob，本地 localStorage 降级为缓存（断网可查看、可编辑，恢复联网后整份文档写回）。选 Blob 而非 KV/Postgres：每个文档就是一个 JSON blob，现有 `mindnb:v2:*` key 结构原样平移，无关系查询需求；平台级生产环境密码保护是 Pro 功能，Hobby 用不上，故在应用层做共享密钥鉴权（`Authorization` 头 + 全屏密码门，密钥存环境变量）。

## Considered Options

- **本地优先 + 后台合并**：被否——单用户场景不需要树级冲突合并，复杂度差一个数量级。冲突处理取「last-write-wins + 覆盖警告 + 版本历史（最近 10 份）」。
- **索引整份 LWW**：被否——索引是单 key，整份覆盖会丢掉其他设备离线新建的文档。索引写入改为服务端按 id 逐条合并、各保留 `updatedAt` 较新；删除改为打墓碑标记而非移除条目（墓碑 30 天后清理）。
- **视图态留本地**：被否——平移/缩放视图与其他数据同管道同步，零特殊处理；最后使用的设备说了算。

## Consequences

- 在 Vercel Hobby 免费额度内运行：Blob 500MB、1200 次简单操作/分钟，单用户绰绰有余。
- `vercel.app` 默认域名在国内直连不稳定，已明确接受（不绑自定义域名）。
- 每台设备首次连接时把本地文档按 id 合并上传（保留较新），此后本地永久降级为缓存。
