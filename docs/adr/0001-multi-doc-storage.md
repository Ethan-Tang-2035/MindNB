# 多文档存储：索引 + 每文档一个 key

单 key（v1 `mindnb:v1`）存整棵树的结构撑不起多文档：换文档列表就得全量读写所有树，localStorage 5MB 配额下的失败面也最大。决定改为 v2 布局：`mindnb:v2:docs` 存文档元数据有序数组（显示顺序即数组顺序），`mindnb:v2:doc:<id>` 存各自的树。v1 迁移仅在索引 key 不存在时执行一次（v1 原文保留作安全网），存量树成为第一份文档。

顺序语义是刻意的：索引数组顺序就是首页显示顺序——保存/重命名把文档移到最前（「最近编辑在前」），但复制插在被复制项右侧（而非跳到最前），两者无法同时用纯时间戳排序表达，故顺序是显式数据而非派生值。

名称不作为独立必存字段：`nameOverride` 可空，null 时显示中心主题文字（跟随直至覆盖），树仍是唯一事实源，名称覆盖与 `layoutMode` 同级挂在文档元数据上。

视图状态（v4，票据 v4-01）沿用每文档一 key：`mindnb:v2:view:<id>` 存 `{dx, dy, k}`——中心主题屏幕中心相对视口中心的偏移加缩放，而非绝对 tx/ty（画布坐标系把中心主题锚在当前视口中心，相对偏移在窗口尺寸变化后仍能还原）。写盘由编辑器在平移/缩放交互结束时触发，刻意不触顶、不刷 updatedAt：查看不是编辑，「最近编辑」排序只该被真实编辑推动。删除文档时视图键一并清除；副本不继承视图。注（v6-07）：树溢出画布时根锚点会向空侧让位，dx 的「中心偏移」编码以锚点居中为基准 —— 让位态下跨窗口还原可能有一次性小幅漂移（同窗口还原不受影响），下次平移或「适应窗口」即自纠。
