# 窗口变化只改变视图，不改变文档构图

2026-09-11 用户确认：窗口缩小时保持字号、缩放和相对位置，只减少可见范围，需要时主动点击“适应窗口”。因此世界布局必须独立于窗口尺寸；中心主题与游离节点、独立主题、图片和笔迹处于同一稳定坐标系，屏幕居中与可见性调整归视图层。

当前 computeLayout 根据窗口中心及可用宽度移动主树，绝对坐标内容却不动；纯函数实验已复现相对位置改变。本决定替代 ADR-0001 及旧中心主题定义中依赖窗口的居中、让位和视图编码假设。它是已接受的目标契约，代码仍待实现。

本决定补充并行编辑器任务的 [ADR-0014：工作范围与稳定布局坐标](0014-content-grown-work-extent.md)，共享同一套世界布局，不另造一套桌面布局引擎。工作范围约束导航，窗口缩放不增长工作范围，也不修改内容位置；本文进一步规定桌面窗口、DPI、浮层和导出的视图契约。

不选择 resize 自动 fit，因为会反复改变阅读字号；不选择随窗口缩窄节点，因为会改变换行与构图。主动适应窗口仅改变视图。编辑器、缩略图和导出共享世界布局，DOM 浮层和指针共用投影。

后续 Q5 已确认必须支持笔记本半屏编辑，不能设置 800px 最小宽度将该场景排除；按实际可用区域折叠工具和格式面板。Q8 已确认视图按设备分别记忆，桌面版不将一台设备的缩放、位置与下钻同步到另一台设备。

旧文档未保存主树锚点，必须以明确参考画布/旧编辑器布局迁移，不能声称从旧 JSON 恢复唯一历史构图。具体字段、默认世界视点及迁移流程见 [视图恢复实现](../../src/editor-viewport.ts)。
