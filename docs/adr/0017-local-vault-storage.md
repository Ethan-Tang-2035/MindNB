# 桌面文档使用本地资料库与独立资源

编号说明：与并行任务新增的 ADR-0014 避让，本记录使用 ADR-0017。

用户已确认选择完整资料库目录，文档与资源可一起放在 iCloud Drive，视图按设备分别保存。建议桌面模式使用一文档一份版本化 JSON、资料库内不可变资源引用，本机独立保存视图、索引与恢复日志；本地编辑不依赖远端授权。用户已要求能打开 `.mindnb` 文件，现已使用版本化 JSON 工作文件与 ZIP 封装的可携带文件，保存协议见实施记录。

这重新打开 ADR-0001 的 localStorage 布局、ADR-0003 的内嵌 data URL，以及 ADR-0005 的远端真源假设。公开文件与目录便于用户搬迁、外部同步；代价是必须实现跨文件资源晚到、外部编辑、可靠替换与恢复，不能借 localStorage 同步接口掩盖失败。

拒绝把整个资料库正文放进需同步的 SQLite/WAL；SQLite 可作本机可重建索引。工作格式不强行使用 Markdown，以免损失图表、笔迹与布局。建议可携带 `.mindnb` 文件包含正文和资源，库内采用独立命名的 JSON 工作文件；不能让同一扩展名无说明地同时代表缺图片的裸 JSON 与完整包。Q10 已确认外部 `.mindnb` 导入所选资料库后打开，修改保存到资料库，外部原文件不自动更新；需要带走时重新导出。

Q7 已明确通过旧网页导出、桌面导入完成一次性迁移，首版不要求两者持续双向编辑；保留旧端与导出包，不包含停服或删除旧数据的授权。

已实现并验证本地封装、异步提交、日志恢复、版本历史及回收站；本 ADR 接受本地资料库决策。旧网页存储链继续保留。iCloud 的跨设备保证不由本 ADR 推断，仍以 ADR-0016 的独立验收为准。详细机制与验证见 [资料库实现](../../desktop/vault.ts)。
