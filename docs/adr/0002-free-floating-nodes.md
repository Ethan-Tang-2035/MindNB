# 游离节点：文档 = 树 + 游离集合

v1～v4 里树是唯一事实源且不含任何坐标，布局全自动，这撑不住「节点游离 + 磁吸挂回」：游离的节点必须带手工坐标存续。决定把文档模型扩为「树 + 游离集合」：游离集合是一批带画布坐标的 NodeData 子树（可折叠、可删除，与树上节点同构），游离期间完全不参与布局计算；磁吸挂回即把该子树并回树上并丢弃其坐标，恢复自动重排。中心主题不进游离集合——它锚定「文档」语义（名称跟随、固定画布中心），是游离语义的参照物。

考虑过两个替代：给全部树节点加可选坐标（混合模型）——树部分布局仍是自动的，坐标对树节点是死数据，还会把拖拽劈成「结构拖」和「位置拖」两类语义，复杂度双份，弃；游离放独立 sheet/画布——用户心智是「在同一张纸上涂鸦」，拆页违背磁吸一键挂回的初衷，弃。实现注意：游离集合与树同级进撤销历史与存储 schema；缩略图渲染两处内容；键盘导航网只覆盖树，游离节点靠鼠标选中、其内部子树导航照旧。
