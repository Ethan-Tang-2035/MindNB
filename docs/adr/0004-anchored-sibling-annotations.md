# ADR-0004 锚定兄弟组：外框与概要

对齐 XMind 的两个标注能力——外框（boundary）与概要（summary）——需要「圈住一组树上兄弟」的元素。既有概念装不下：分组框用几何包含、刻意「永不圈树上的节点」（ADR-0003）；树节点自己更不会带框。决定新增两种画布对象，共享同一套**锚定兄弟组**机制。

## 决策

- **两种对象进 `MindMap.objects`**：`boundary`（外框）与 `summary`（概要）作为 CanvasObject 新成员，复用 objects 通道的撤销快照、存储 schema、z 序数组——不为它们另立顶层集合。
- **锚定是位置区间，不是节点身份**：`{ parentId, start, count }` 指向「锚定时该父下从 start 起连续 count 个兄弟」。树上兄弟增删/移动后由 model 层统一收缩调整区间（区间前插入 start++，区间内删除 count--）；count < 2 即对象消亡。不追踪节点 id——XMind 同样圈的是「位置上的兄弟」，语义可预期且免维护成员清单。
- **坐标派生，不存储**：外框/概要不存 x/y/seed，渲染时从布局读锚定兄弟盒并集推导（外框=并集+内边距的手绘圆角框；概要=并集外侧的大括号+文字盒）。这与 CONTEXT.md「画布对象：自带画布坐标」的一般定义不同——锚定族的坐标是布局的函数，这正是「随布局重排自动跟随」的来源。
- **概要文字不是树上节点**：双击可编辑的一段文字，不进键盘导航网、不能连关系线、不能有子节点。做成真节点会污染布局与导航语义；概要本质是「对一组兄弟的标注」。
- **层序**：外框/概要与分组框同层（渲染在树节点之下），框里框外节点照常命中——标注不挡内容。

## 刻意取舍

- **标注式，不是真分组**：grill 中确认过「树上节点成组拖动」的选项，明确放弃——那会推翻「分组框永不圈树上节点」的边界，把树节点变成可整体搬移的块，动摇树的布局模型。外框=树上强调，分组框=游离容器，两个词各管一半。
- **位置锚定的代价**：把区间中间的兄弟跨父拖走，外框不会跟着他走（他不再在那个位置）。这是刻意的：锚定身份则要在挂接/删除/移动的每条路径上维护成员一致性，几何与位置语义零维护，与分组框「几何包含」的取舍一脉相承。
